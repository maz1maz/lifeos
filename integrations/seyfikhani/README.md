# اتصال seyfikhani.ir ⇄ LifeOS (پنل خصوصی ملینا)

صفحهٔ خصوصی `studio.html` روی سایت ملینا که «پروژه‌ها» و «دوره‌ها و دانشجوها» را **زنده** از LifeOS می‌خواند و همان‌جا می‌نویسد.
منبع داده فقط LifeOS است (کپی جدا نیست) ⇒ تغییر در هر طرف، در طرف دیگر دیده می‌شود (سایت هر ۳۰ ثانیه و با «به‌روزرسانی» دوباره می‌خواند).

## معماری
```
مرورگر ملینا ──(کوکی نشست + CSRF)──▶ studio-api.php (cPanel) ──(Bearer lfs_… فقط سمت سرور)──▶ LifeOS Worker /api/ext/*
```
- **ورود:** فقط ایمیل `login_email` + رمز جدای سایت (هش PBKDF2 در فایل تنظیمات). ۵ تلاش ناموفق/۱۵ دقیقه برای هر IP، ۲۰ در ساعت کل.
- **نشست:** کوکی `HttpOnly; Secure; SameSite=Strict`، خروج خودکار بعد از ۲ ساعت بی‌کاری و حداکثر ۱۲ ساعت.
- **توکن LifeOS:** فقط در `lifeos-studio-config.php` بیرون از `public_html`؛ مرورگر هرگز آن را نمی‌بیند. LifeOS فقط SHA-256 آن را نگه می‌دارد و از تنظیمات قابل لغو است.
- **دسترسی محدود:** پروکسی فقط مسیرهای مجاز `/api/ext/*` را رد می‌کند؛ توکن هم فقط به مجموعه‌های scope خودش دسترسی دارد:
  - `projects` → projects، cards، projectProcesses، یادآوری‌های وصل به پروژه
  - `courses` → courses، students، پرداخت‌ها (+ تراکنش «آموزش» در مالی، اگر تیک بخورد)، یادآوری‌های وصل به دوره
  - `projectFiles` → قرارداد، صورت‌وضعیت‌ها و تأمین/اجرا (تیک جدا در LifeOS). «تاریخ اتمام قرارداد» یادآوری «تمدید قرارداد» را یک هفته قبل در LifeOS می‌سازد/جابه‌جا می‌کند.
- **یادآوری‌ها:** یادآوری سایت یک ردیف واقعی در `db.reminders` است (با ساعت) ⇒ cron پنج‌دقیقه‌ای LifeOS آن را به تلگرام/Push می‌فرستد. «تاریخ یادآوری» روی مرحلهٔ پروژه هم همان یادآوری را می‌سازد/جابه‌جا/حذف می‌کند.
- `projects.html` عمومی دست نخورده؛ فقط یک لینک کوچک «ورود» در فوتر همهٔ صفحه‌ها اضافه می‌شود. `studio.html` با `noindex` و `robots.txt` از موتور جست‌وجو پنهان است.

## فایل‌ها
| فایل | مقصد روی هاست |
|---|---|
| `public_html/studio.html` + پوشهٔ `studio-assets/` (ساخته‌شده با `npm run build:studio` از `src/today/src/studio.jsx` = همان `ProjectsPage` و `CoursesPage` خود LifeOS) و `studio-api.php` | `public_html/` (فایل‌های قدیمی `studio.js` و `studio.css` را پاک کن) |
| `lifeos-studio-config.sample.php` → با نام `lifeos-studio-config.php` | پوشهٔ home (یک سطح **بالای** `public_html`) |
| `add-login-link.js` | اجرا روی نسخهٔ محلی `public_html` قبل از آپلود (آیکن قفل در منوی دسکتاپ + لینک «ورود» فوتر + robots) |
| `make-password-hash.js` | اجرا روی کامپیوتر خودت برای ساخت هش رمز |

## مراحل انتشار
1. **LifeOS:** `npm run deploy` (با اجازه). سپس با حساب **ملینا** وارد LifeOS شو → تنظیمات → «🌐 اتصال سایت شخصی» → «پروژه‌ها»، «دوره‌ها» و «قرارداد، مالی و تأمین» تیک → «ساخت توکن» → توکن را کپی کن (فقط یک بار نشان داده می‌شود).
2. **تلگرام ملینا:** در همان حساب، تنظیمات → «اتصال تلگرام» باید «متصل است» باشد؛ وگرنه یادآوری ذخیره می‌شود ولی پیام نمی‌رسد.
3. **رمز سایت:** `node integrations/seyfikhani/make-password-hash.js` → رمز (حداقل ۱۰ کاراکتر، غیر از رمز Gmail/LifeOS) → خروجی `pbkdf2_sha256$…` را نگه دار.
4. **فایل تنظیمات:** از sample یک `lifeos-studio-config.php` بساز، `lifeos_token` و `password_hash` را پر کن، در cPanel → File Manager در **home** (کنار `public_html`، نه داخلش) آپلود کن، دسترسی `600`.
5. **فایل‌های سایت:** چهار فایل `studio*` را در `public_html` آپلود کن؛ صفحه‌های HTML و `robots.txt` که `add-login-link.js` تغییر داده را جایگزین کن (یا فقط لینک فوتر را دستی اضافه کن).
6. **PHP:** نسخهٔ PHP ≥ 8.0 با افزونهٔ `curl` (در cPanel → MultiPHP / Select PHP Version).
7. **آزمون واقعی:** `https://www.seyfikhani.ir/studio.html` → ورود → یک یادآوری برای ۱۰ دقیقهٔ بعد بساز → در LifeOS (برنامه‌ریز) ببین → منتظر پیام تلگرام بمان. یک تغییر هم در LifeOS بده و در سایت «به‌روزرسانی» بزن.

## لغو اضطراری
LifeOS → تنظیمات → «اتصال سایت شخصی» → «لغو». سایت بلافاصله قطع می‌شود (خطای «توکن نامعتبر»).

## محدودیت‌های فعلی
- لغو/جابه‌جایی جلسهٔ دوره، پیام گروهی، خروجی اکسل/چاپ و رسید فقط داخل LifeOS.
- حذف پروژه/دوره‌ای که زیرمجموعه دارد از سایت مجاز نیست (۴۰۹)؛ از LifeOS حذف شود.
- ویرایش همزمان یک فیلد در دو طرف: آخرین ذخیره برنده است (مثل بقیهٔ LifeOS).
- `/api/ext/*` فقط در `cloudflare/worker.js` است؛ `server.js` اصلاً `/api/col/*` ندارد (بدهی آشتی Worker/Node).

## ظاهر = خود LifeOS
پنل همان کامپوننت‌های React صفحه‌های «پروژه‌ها» و «دوره‌ها و دانشجوها»ی LifeOS است (`studio.jsx`).
`api()` در `life.jsx` اگر `window.__lifeosApi` باشد از آن استفاده می‌کند؛ studio مسیرها را این‌طور می‌فرستد:
`/api/col/*` → `/api/ext/col/*` · `/api/reminders*` → `/api/ext/reminders*` · `/api/transactions*` (فقط «آموزش») → `/api/ext/transactions*`.
هر تغییر در این صفحه‌های LifeOS ⇒ `npm run build:studio` و آپلود دوبارهٔ `studio.html` + `studio-assets/`.
«ارسال گزارش به تلگرام» از سایت هم کار می‌کند (PDF تکه‌تکه از پروکسی به `/api/ext/report-chunk` و `report-send` می‌رود). پیوست‌ها فقط داخل خود LifeOS.
خلاصهٔ فرم‌ها (مشاوره، طراحی نما، ثبت‌نام دوره، تماس) بی‌درنگ با `POST /api/ext/notify` بدنه `{ "text": "…" }` به تلگرام صاحب توکن می‌رود (هر scope، سقف ۶۰ پیام در ساعت برای هر توکن، حداکثر ۳۹۰۰ نویسه؛ ۵۰۳ = تلگرام وصل نیست).

## شبکهٔ هاست ایرانی
- هاست درخواست‌هایی که هدر `Authorization` دارند را نگه می‌دارد ⇒ توکن با `X-LifeOS-Token` فرستاده می‌شود.
- جواب‌های بزرگ‌تر از ~۶۴KB وسط راه قطع می‌شوند ⇒ پروکسی فهرست‌ها را ۲۵تایی (`?offset=&limit=`) و با gzip می‌گیرد.
- عیب‌یابی (بعد از ورود، آدرس را در نوار آدرس بچسبان): `studio-api.php?a=diag` و `studio-api.php?a=diag&lists=1`.

## تغییر رمز توسط خود ملینا
در پنل، دکمهٔ 🔑 «تغییر رمز» (رمز فعلی + رمز تازهٔ حداقل ۱۰ کاراکتر). هش تازه در `lifeos-studio-data/password-hash.txt` (بیرون از `public_html`) ذخیره می‌شود و بر `password_hash` فایل تنظیمات مقدم است.
رمز فراموش شد؟ در cPanel همان `password-hash.txt` را پاک کن؛ رمز فایل تنظیمات دوباره کار می‌کند.
